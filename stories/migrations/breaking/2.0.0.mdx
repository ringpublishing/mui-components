# Breaking version upgrades — 2.0.0

2.0.0 renders the redesigned Ring design system by default, draws its icons with lucide, removes `ChipsInput` and
re-namespaces the `data-testid` attributes. This page lists every breaking change between 1.19.0 and 2.0.0: for each
one, where it shows in an application, what to change and a before/after example.

The examples assume React 18 or 19, MUI 7, TypeScript 5, `@ringpublishing/mui-theme` 5, `lucide-react` 1.42 or later
and `ThemeConfig` at the application root; the unit-test examples use Testing Library, the e2e ones
Playwright.

## Upgrade in this order

1. Upgrade `@ringpublishing/mui-theme` to 5, then the components — [Theme and Emotion are peer dependencies](#200---theme-and-emotion-are-peer-dependencies), and check [the theme's own breaking changes](#200---theme-5-breaking-changes).
2. Install `lucide-react`, drop `@mui/icons-material` — [Icons](#200---icons-muiicons-material--lucide-react).
3. Load the Inter font — [Components render the redesign by default](#200---components-render-the-redesign-by-default).
4. Call `enableTreeDynamicLoading()` if a tree uses `loadItems` — [Tree dynamic loading](#200---simpletree-and-datatree-dynamic-loading-is-opt-in).
5. Fix what no longer compiles: [`ChipsInput`](#200---chipsinput--autocomplete-variantchipsinput), [`AutocompleteChangeReason`](#200---autocompletechangereason-is-a-local-union-with-reorder), [`AutocompleteProps`](#200---autocompleteprops-includes-the-chipsinput-variant), [`AutocompleteLabels.title`](#200---autocompletelabelstitle-is-a-reactnode), [`ActionBox` props](#200---actionbox-renders-a-mui-menu), [deep imports](#200---deep-imports-from-dist-no-longer-resolve), [`version`](#200---themeconfig-and-getcreatedtheme-take-no-version).
6. Run the test suites: [`data-testid` audit](#200---data-testid-audit--renamed-and-re-namespaced-selectors), [chip delete glyph](#200---chip-delete-glyph-is-the-lucide-x), [icon test ids](#200---icons-muiicons-material--lucide-react), DOM snapshots.
7. Review the screens: [Accordion](#200---accordion-summary-column-layout), [FiltersWrapper](#200---filterswrapper-input-variant), [date and time pickers](#200---date-and-time-picker-field-variant), [typography variants](#200---typography-variants-migrated-to-standard-ones), [Detail icons](#200---detail-field-icon-slot-owns-its-icon), [icon sizes](#200---plain-lucide-icons-take-the-design-systems-size-and-stroke).

## [2.0.0] - Theme and Emotion are peer dependencies

`@ringpublishing/mui-theme`, `@emotion/react` and `@emotion/styled` are peer dependencies instead of dependencies. The
application installs one copy of each; the components, `ThemeConfig` and your own code share it.

### Where to look

- `package.json` lists `@ringpublishing/mui-theme` 4.x, or does not list it at all because 1.x installed it.
- `npm install @ringpublishing/mui-components@^2` stops with `ERESOLVE`:

```text
npm error code ERESOLVE
npm error ERESOLVE unable to resolve dependency tree
npm error While resolving: my-app@1.0.0
npm error Found: @ringpublishing/mui-theme@4.10.1
npm error node_modules/@ringpublishing/mui-theme
npm error   @ringpublishing/mui-theme@"^4.10.1" from the root project
npm error Could not resolve dependency:
npm error peer @ringpublishing/mui-theme@"^5…" from @ringpublishing/mui-components@2.0.0
```

### What to change

Upgrade the theme to 5 before the components. The package manager resolves the new peer dependency against the copy
that is already installed, so the order matters.

**npm** (7 and later) — two commands, in this order. Both packages in one command stop with the same `ERESOLVE` while
1.x is installed:

```bash
npm i @ringpublishing/mui-theme@^5
npm i @ringpublishing/mui-components@^2
```

npm removes `@mui/icons-material` on its own when nothing else depends on it, and installs `lucide-react`.

**pnpm** (8 and later) — both in one command. `pnpm add @ringpublishing/mui-components@^2` alone succeeds with a warning
(`✕ unmet peer @ringpublishing/mui-theme@^5…: found 4.10.1`) and leaves the components on theme 4:

```bash
pnpm add @ringpublishing/mui-components@^2 @ringpublishing/mui-theme@^5
```

**yarn 1** does not install peer dependencies: it warns and keeps theme 4. Add the three packages yourself:

```bash
yarn add @ringpublishing/mui-components@^2 @ringpublishing/mui-theme@^5 @emotion/react @emotion/styled
```

Do not silence `ERESOLVE` with `--force` or `--legacy-peer-deps`: the application keeps theme 4, which 2.0.0 does not
support, and `--legacy-peer-deps` skips every other peer dependency as well, `lucide-react` and Emotion included.

### Before and after

```diff
 "dependencies": {
-    "@ringpublishing/mui-components": "^1.19.0",
-    "@ringpublishing/mui-theme": "^4.10.1"
+    "@emotion/react": "^11.14.0",
+    "@emotion/styled": "^11.14.0",
+    "@ringpublishing/mui-components": "^2.0.0",
+    "@ringpublishing/mui-theme": "^5.0.0",
+    "lucide-react": "^1.42.0"
 }
```

Declare the theme even where the package manager would install it for you: every component renders with it, so its
version should be one you chose.

## [2.0.0] - Theme 5 breaking changes

`@ringpublishing/mui-theme` 5 changes more than the components' look. The entries below break application code; the
full list is in the `CHANGELOG.md` shipped with `@ringpublishing/mui-theme`.

### Where to look

```bash
rg "::-webkit-scrollbar|scrollbar-bg|components\.detail\.close|components\.mediaImage|(contrast|primary|secondary|error|warning|info|success|text)\.(hover|selected|focus|focusVisible|outlinedBorder|contrast)\b|paper-elevation|elevation\.(outlined|Color)|avatar\.fill|slideFill|chip\.default(CloseFill|HoverFill|EnabledBorder|FocusFill)|skeleton\.border|externalComponentsTheme|styleOverrides|slotProps=\{\{\s*paper"
```

- `::-webkit-scrollbar*` rules, `display: none` included: the theme sets `scrollbar-width` on every element and
  `scrollbar-color` on `html`, so Chromium 121+ and Safari 18.2+ ignore them.
- `palette._native['scrollbar-bg']`, `palette.components.detail.close`, `palette.components.mediaImage` and the
  `hover`, `selected`, `focus`, `focusVisible`, `outlinedBorder` and `contrast` slots of `palette.contrast`: withdrawn.
  They read `undefined`, the theme's types do not declare them, and an `sx` path to one sets no colour.
- Other palette keys of the 4.x theme that the redesign does not define: the `hover`, `selected`, `focus`,
  `focusVisible`, `outlinedBorder` and `contrast` slots of `primary`, `secondary`, `error`, `warning`, `info`, `success`
  and `text`, `background['paper-elevation-*']`, `elevation.outlined`, `elevation.Color`,
  `palette.components.avatar.fill`, `switch.slideFill`, the `chip.default*` slots and `skeleton.border`. They read
  `undefined` and an `sx` path to one, such as `bgcolor: 'primary.hover'`, sets no colour. TypeScript does not catch a
  read: most were never declared and the rest are optional, so search for them; the theme's `CHANGELOG.md` lists them
  exactly.
- An entry in `externalComponentsTheme` for a component the theme now defines — `MuiButton`, `MuiIconButton`,
  `MuiCheckbox`, `MuiSwitch`, the inputs (`MuiInputBase`, `MuiInput`, `MuiFilledInput`, `MuiInputAdornment`,
  `MuiFormHelperText`), the date and time pickers and their fields, `MuiSimpleTreeView`, `MuiRichTreeView` and
  `MuiDataGrid`: the theme's own entry replaces yours instead of merging with it, so what you set there, such as a
  grid's `density`, no longer applies. The theme's `CHANGELOG.md` names every key.
- An object in `themeOverrides.components` for a slot the theme styles with a function — `MuiButton.root`,
  `MuiIconButton.root`, `MuiChip.root`, `MuiSwitch.root` and the input roots among them: it replaces the theme's style
  instead of adding to it, so one `minWidth` on `MuiButton.root` brings back MUI's uppercase label and 4px corners, and
  one margin on `MuiSwitch.root` brings back MUI's own switch. The theme's `README.md` lists every such slot.
- An `Autocomplete` `slotProps.paper` passed as a function: ignored; the list opens on elevation 8.

### What to change

Style or hide scrollbars with `scrollbar-width` and `scrollbar-color`. Read `palette._native.scrollbarBackground` for
the scrollbar thumb, use `color="overlay"` for controls over imagery and `palette.components.media.backgroundFill` for a
media frame, and replace a `palette.contrast` state with `alpha(palette.contrast.main, palette.action.<state>Opacity)`.
Derive the other state colours the same way from `palette.<colour>.main`, and use `palette.divider` for borders and
`palette.background.paper` for surfaces. For a slot the theme styles with a function, pass a function that repeats the
styles you keep, or style the element with `sx` where you render it.
Move the entries for the components above to `themeOverrides.components`. Move a `MuiDataGrid` entry there too and spread
`ringDataGridOverrides.MuiDataGrid` from `@ringpublishing/mui-theme/mui-x` into it: an entry of your own replaces the
grid defaults `ThemeConfig` adds, so without them the grid shows its footer again and its column titles change colour.
Typing `MuiDataGrid` in `themeOverrides.components` needs MUI X's theme augmentation. Pass `slotProps.paper` as an
object.

### Before and after

```tsx
// before
<Box sx={{ overflowX: 'auto', '&::-webkit-scrollbar': { display: 'none' } }} />
<Autocomplete slotProps={{ paper: () => ({ elevation: 2 }) }} … />

// after
<Box sx={{ overflowX: 'auto', scrollbarWidth: 'none' }} />
<Autocomplete slotProps={{ paper: { elevation: 2 } }} … />
```

```tsx
// before
<ThemeConfig mode="light" externalComponentsTheme={{ MuiDataGrid: { defaultProps: { density: 'compact' } } }}>
    <App />
</ThemeConfig>;

// after
import type {} from '@mui/x-data-grid/themeAugmentation';
import { ringDataGridOverrides } from '@ringpublishing/mui-theme/mui-x';

<ThemeConfig
    mode="light"
    themeOverrides={{
        components: {
            MuiDataGrid: {
                ...ringDataGridOverrides.MuiDataGrid,
                defaultProps: { ...ringDataGridOverrides.MuiDataGrid.defaultProps, density: 'compact' },
            },
        },
    }}
>
    <App />
</ThemeConfig>;
```

## [2.0.0] - Components render the redesign by default

`ThemeConfig` and `getCreatedTheme` build the redesigned Ring design system instead of the 1.x look: a new palette,
typography set in Inter, a new spacing and border-radius scale and design-system shadows.

### Where to look

- Every screen changes look on upgrade, with no code change.
- Text renders in the system font (Helvetica on macOS) instead of Inter: the theme names the font but does not load
  it, and nothing had to until now because 1.x used Arial. The build and the console stay clean, so check
  in DevTools: **Elements → Computed → Rendered Fonts** names Inter, and the **Network** panel filtered to **Font**
  lists `inter-*.woff2` files.
- The first render waits for Inter: `ThemeConfig` renders its children once the Inter files the page declares have
  loaded, at most 2 seconds after it mounts. If they load slowly or fail, the page stays blank for up to 2 seconds.
  Tests in jsdom render at once: jsdom loads no fonts.
- `Typography` with `variant="headline1"`, `headline2`, `headline3` or `label`: the theme no longer defines them.
  They still type-check and render unstyled — see
  [Typography variants migrated to standard ones](#200---typography-variants-migrated-to-standard-ones).

### What to change

Install the font and import the weights the theme uses once, in the application entry file. Use `@fontsource/inter`,
not `@fontsource-variable/inter`: the variable package registers the font as `Inter Variable`, a name the theme does not
look for. To link the font from Google Fonts instead, see
[Setup → Load the Inter font](?path=/docs/introduction-setup--docs#load-the-inter-font).

```bash
npm install @fontsource/inter
```

```javascript
import '@fontsource/inter/300.css';
import '@fontsource/inter/400.css';
import '@fontsource/inter/500.css';
import '@fontsource/inter/600.css';
import '@fontsource/inter/700.css';
```

`waitForFonts={false}` on `ThemeConfig` renders the children at once; the text switches to Inter when the files arrive.

Then review the places where the look changes most: palette (a slate-based scale), border radius
(`theme.getBorderRadius()`), shadows (design-system elevations instead of MUI defaults) and typography.

### Before and after

```tsx
// before — 1.x set the text in Arial, so the entry file loaded no font
import { ThemeConfig } from '@ringpublishing/mui-components';

<ThemeConfig mode="light">
    <App />
</ThemeConfig>;

// after — the same ThemeConfig renders the redesign in Inter; load the weights it uses
import '@fontsource/inter/300.css';
import '@fontsource/inter/400.css';
import '@fontsource/inter/500.css';
import '@fontsource/inter/600.css';
import '@fontsource/inter/700.css';
import { ThemeConfig } from '@ringpublishing/mui-components';

<ThemeConfig mode="light">
    <App />
</ThemeConfig>;
```

## [2.0.0] - `ThemeConfig` and `getCreatedTheme` take no `version`

`ThemeConfigProps` and `GetCreatedThemeOptions` no longer have a `version` field. `ThemeConfig` and `getCreatedTheme`
render the redesigned Ring design system described in
[Components render the redesign by default](#200---components-render-the-redesign-by-default).

### Where to look

A `version` written on `ThemeConfig` or in the options literal of `getCreatedTheme` stops compiling. TypeScript reports
`TS2322` on `ThemeConfig` and `TS2353` on `getCreatedTheme` (`TS2345` on older TypeScript versions), with:

```text
Property 'version' does not exist on type 'IntrinsicAttributes & ThemeConfigProps'.
Object literal may only specify known properties, and 'version' does not exist in type 'GetCreatedThemeOptions'.
```

TypeScript does not report a `version` that reaches them through a spread, or through an options object built
beforehand together with other options, so search for it as well:

```bash
rg -n --hidden "\bversion\b[^\n]*['\"](next|reference)['\"]|\bThemeVersion\b" --glob '!node_modules' --glob '!.git'
```

### What to change

Remove `version` from `ThemeConfig`, from the options of `getCreatedTheme`, and from the props or options objects
spread or passed into them. Then review the screens against the redesign.

### Before and after

```tsx
// before
<ThemeConfig mode="light" version="reference">
    <App />
</ThemeConfig>;

const theme = getCreatedTheme('light', { language: CommonLanguages.plPL, version: 'reference' });

// after
<ThemeConfig mode="light">
    <App />
</ThemeConfig>;

const theme = getCreatedTheme('light', { language: CommonLanguages.plPL });
```

## [2.0.0] - Typography variants migrated to standard ones

The theme no longer defines the `headline1`, `headline2`, `headline3` and `label` variants. The library stopped using
them: `Detail` field names and the `Placeholder` footer render `caption`, `Detail` section titles and the `FileUploader`
heading render `subtitle2`, the `FiltersWrapper` heading renders `subtitle1`. Font sizes are unchanged and the
uppercase transform is gone.

### Where to look

- Your own `Typography` with one of the four variants. They type-check, because the augmentation is global, and render
  unstyled, so grep for them:

```bash
rg -e "variant(=\{?| ?: ?)['\"](headline[123]|label)['\"]" -e "typography(\.|: ?['\"])(headline[123]|label)\b"
```

- CSS or tests keyed on `.MuiTypography-headline1`, `-headline2`, `-headline3` or `-label` inside `Detail`,
  `Placeholder`, `FileUploader` and `FiltersWrapper`.

### What to change

Pick the standard variant with the size you need and state the weight or transform you want to keep, as the library
did. In 1.x `headline2` was 14px / 24px, semibold, uppercase.

### Before and after

```tsx
// before
<Typography variant="headline2">Payment details</Typography>

// after — subtitle2 is 14px and semibold
<Typography variant="subtitle2" sx={{ textTransform: 'uppercase' }}>
    Payment details
</Typography>
```

## [2.0.0] - Icons: `@mui/icons-material` → `lucide-react`

The library draws its icons with [lucide](https://lucide.dev/icons/). `lucide-react` (`^1.42.0`) is a peer dependency
and `@mui/icons-material` is not.

### Where to look

- `@mui/icons-material` in `package.json` and in imports: `rg "@mui/icons-material"`.
- Material icons passed into components as elements — an `icon` in `ActionBox` actions, a `startIcon`, an
  `IconButton` child. They are ordinary React elements, so they keep rendering and type-checking; what changes is the
  look, because the library's own icons are 20px lucide strokes and a filled 24px Material glyph next to them stands out.
- Tests that find an icon the library draws by the `data-testid` MUI gives its icons outside production builds
  (`MoreVertIcon`, `ExpandMoreIcon`, `CloseIcon`, …): lucide icons carry none.

```bash
rg "TestId\(['\"][A-Za-z]+Icon['\"]\)|data-testid=['\"]?[A-Za-z]+Icon\b"
```

### What to change

Install `lucide-react`; drop `@mui/icons-material` once nothing else in the application needs it (npm removes it on its
own when it was installed only as a peer of 1.x).

```bash
npm install lucide-react
```

Swap the icons screen by screen. The [Icon Map](?path=/docs/migration-faq-breaking-version-upgrades-2-0-0-icon-map--docs)
lists replacements for the Material icons used in Ring Publishing modules, two of them Ring glyphs from
`@ringpublishing/mui-components/icons`; for an icon not listed, find the equivalent on
[lucide.dev](https://lucide.dev/icons/). The common names:

| `@mui/icons-material`                 | `lucide-react`     |
| ------------------------------------- | ------------------ |
| `Delete`                              | `Trash2`           |
| `Edit`                                | `Pencil`           |
| `Close`                               | `X`                |
| `Add`                                 | `Plus`             |
| `MoreVert`                            | `EllipsisVertical` |
| `ExpandMore`                          | `ChevronDown`      |
| `Warning`                             | `TriangleAlert`    |
| `Visibility`                          | `Eye`              |
| `ContentCopy`                         | `Copy`             |
| `Search`, `Check`, `Info`, `Settings` | same name          |

Under `ThemeConfig` a plain lucide icon takes the same props a Material icon did, with one gap:

| Prop                                        | Material icon (1.x) | lucide icon (2.0.0)                                                                                                                   |
| ------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `color="error"` and the other palette names | works               | works                                                                                                                                 |
| `fontSize="small" / "medium" / "large"`     | 20 / 24 / 32px      | 20 / 24 / 32px                                                                                                                        |
| no size prop                                | 24px                | **20px** — the design system default                                                                                                  |
| `sx`                                        | works               | **type error** (`Property 'sx' does not exist`); without TypeScript it styles nothing — use `<RingLucideIcon icon={Trash2} sx={…} />` |
| glyph                                       | filled              | 1.5px stroke at every size                                                                                                            |

`fontSize` wins over lucide's `size` when both are set. Everything a lucide icon gets under `ThemeConfig`, when to use
`RingLucideIcon`, and the Ring glyphs are on the [Icons](?path=/docs/design-icons--docs) page.

In tests, select the control the icon sat in by its role and accessible name: an actions menu button is `More actions`,
an `Alert` close button `Close`, a `SortableList.DragHandle` `Drag to reorder`.

### Before and after

```tsx
// before
import DeleteIcon from '@mui/icons-material/Delete';
<DeleteIcon color="error" fontSize="small" />;

// after
import { Trash2 } from 'lucide-react';
<Trash2 color="error" fontSize="small" />;
```

```tsx
// before
fireEvent.click(screen.getByTestId('MoreVertIcon'));

// after
fireEvent.click(screen.getByRole('button', { name: 'More actions' }));
```

## [2.0.0] - Plain lucide icons take the design system's size and stroke

`ThemeConfig` mounts `RingIconDefaults`, which hands every plain `lucide-react` icon under it the design system's 20px
size and 1.5px stroke instead of lucide's 24px and 2px. Explicit props on an icon still win.

### Where to look

- An application that already used `lucide-react` with 1.x: its icons shrink by 4px and their strokes get thinner on
  upgrade, with no code change.
- Icons swapped one-to-one from Material without a size prop: 24px before, 20px now.
- Strokes that still scale with the icon (1.25px at 20px instead of 1.5px): the application has a `lucide-react` older
  than 1.42, which ignores the non-scaling stroke `RingIconDefaults` sets.
- Icons at 24px with a 2px stroke — the default icons of `Alert` and the date pickers, and the components' own icons
  among them: the application builds its theme with `getCreatedTheme` and its own `ThemeProvider`, so nothing mounts
  `RingIconDefaults`.

### What to change

An application with its own `ThemeProvider` mounts `RingIconDefaults` inside it, as
[Icons → Outside `ThemeConfig`](?path=/docs/design-icons--docs#outside-themeconfig-and-overriding-the-defaults) shows.
Upgrade a `lucide-react` older than 1.42 (`npm i lucide-react@^1.42`). Take the design system's size where you can.
Where a screen cannot move yet, `fontSize="medium"` restores 24px on one icon, and `size` / `strokeWidth` on an icon
always win, but the stroke keeps the width you pass at every icon size. To keep lucide's own defaults for a subtree —
24px and a 2px stroke that scales with the icon — wrap it in `lucide-react`'s `LucideProvider`: a nested provider
overrides the one `ThemeConfig` mounted. It is a bridge for the migration, not a setting.

### Before and after

```tsx
// before — lucide's own defaults: 24px with a 2px stroke, which grows with the icon at size={28}
<Save />
<Save size={28} />

// after — under ThemeConfig the same elements render 20px and 28px, both with a 1.5px stroke; to keep lucide's defaults:
import { LucideProvider } from 'lucide-react';

<LucideProvider>
    <Save />
    <Save size={28} />
</LucideProvider>;
```

## [2.0.0] - `absoluteStrokeWidth` on plain lucide icons

`RingIconDefaults` renders every stroke at a fixed pixel width whatever the icon size. lucide's own
`absoluteStrokeWidth` divides the stroke width first and hands the result to that non-scaling stroke, so the two
compound: `<Save absoluteStrokeWidth size={32} />` drew a 2px stroke in an application without `RingIconDefaults` and
draws 1.125px under `ThemeConfig`.

### Where to look

```bash
rg "absoluteStrokeWidth"
```

### What to change

Drop the prop from plain `lucide-react` icons: the stroke is 1.5px at every size without it. `RingLucideIcon` and the
Ring glyphs (`AIPencilIcon`, `EarthOffIcon`, `ListFilterOffIcon`) switch the non-scaling stroke off when they are given
the prop, so they keep working.

### Before and after

```tsx
// before — 2px stroke at 32px
<Save absoluteStrokeWidth size={32} />

// after — 1.5px stroke at 32px
<Save size={32} />
```

A handler whose `reason` is annotated with MUI's type stops compiling, whether or not `sortableChips` is on, because the

## [2.0.0] - `ActionBox` renders a MUI `Menu`

`ActionBox` renders a MUI `Menu` instead of a `Popper`.

### Where to look

- `modifiers`, `popperOptions`, `popperRef` or `transition` on an `ActionBox`: they no longer type-check.
- An `ActionBox` without `placement`: 1.x opened it at `bottom-end`; the menu now opens at MUI's default, below the
  anchor and aligned to its left edge.
- `placement="auto"`, `auto-start` or `auto-end`: the menu opens at MUI's default and logs
  `Auto* placements uses default Menu placement`. The other twelve Popper values still type-check and are mapped.
- The page behind an open menu: `Menu` renders a `Modal`, so page scrolling is locked and the rest of the application
  is hidden from assistive technology while it is open.
- `determineTransformOriginFromPopperPlacement`: no longer exported.

### What to change

Drop the Popper-only props (`disablePortal` and `keepMounted` keep working, `Menu` inherits them from `Modal`). Pass
`placement="bottom-end"` where the menu must stay right-aligned. Pass `disableScrollLock` where the page has to keep
scrolling behind the menu. A `popperRef` used to reposition the menu becomes `action`:
`actionRef.current?.updatePosition()`.

`determineTransformOriginFromPopperPlacement` has no replacement: `ActionBox` maps `placement` itself, and
`anchorOrigin` / `transformOrigin` set the origins directly and win over `placement`. Code that called it for a `Popper`
of its own keeps the mapping in the application:

```tsx
import type { PopperPlacementType } from '@mui/material';

const TRANSFORM_ORIGIN: Partial<Record<PopperPlacementType, string>> = {
    'bottom-start': 'top left',
    'top-start': 'bottom left',
    'top-end': 'bottom right',
    'left-start': 'top left',
    'right-start': 'top left',
    'right-end': 'top left',
};
const transformOrigin = (placement?: PopperPlacementType): string =>
    (placement && TRANSFORM_ORIGIN[placement]) ?? 'top right';
```

### Before and after

```tsx
// before
<ActionBox actions={actions} anchorEl={ref} transition modifiers={[{ name: 'offset', options: { offset: [0, 8] } }]} />

// after — the 1.x alignment, scrolling kept
<ActionBox actions={actions} anchorEl={ref} placement="bottom-end" disableScrollLock />
```

## [2.0.0] - `Detail` field icon slot owns its icon

A `Detail` field renders its value and its `icon` in one row. The icon slot is one line of the value tall and centres
what it is given, so a long value wraps beside the icon instead of pushing it under the text. The slot sizes only a bare
icon: an icon passed directly (`icon: <Globe />`) takes the field's 20px, an icon wrapped in another element

- Fields whose `icon` is wrapped in a `span`, `Box` or a component of your own: the wrapper was forced to 20px and is

icon with its own `onClick` can become a `CopyIconButton`, which brings the confirmation, tooltip and live region. A
field with a long value can keep one line with `truncate: 'middle'`: the start and the last 12 characters stay visible,
the full value is in a tooltip and the whole value stays in the DOM for selection, copying and screen readers.

### Before and after

```tsx

// after
```

### What to change

Call `enableTreeDynamicLoading()` once, in code that runs in the browser before such a tree renders: the application
entry, the module that renders the tree, or a client module in a React Server Components app. Make the same call in the
test setup file if tests render trees with `loadItems`. Without `@tanstack/react-query` installed the call breaks the
app: webpack, Rspack and Vite 7 or older fail the build; Vite 8 only warns, and the app fails when a tree with
`loadItems` loads, or at startup if a `manualChunks` rule puts the library in a vendor chunk. An application that installed `@tanstack/react-query`
only to get past a startup error, and does not use `loadItems`, can remove it.

### Before and after

```tsx
// before — loadItems worked with no setup
<SimpleTree items={[{ itemId: 'root', label: 'Root', loadItems: fetchChildren }]} />;

// after — once, in the application entry
import { enableTreeDynamicLoading } from '@ringpublishing/mui-components/tree-dynamic-loading';

enableTreeDynamicLoading();
```

## [2.0.0] - `data-testid` audit — renamed and re-namespaced selectors

The `data-testid` attributes follow one convention: `ring-<component>[-<suffix>]` on the root, `-item-<id>` (or
`-item-<index>` where items have no id) on repeated children, and `<owner-id>-…` for anything a component renders on
another component's behalf. Several attributes moved or were renamed as a result.

### Where to look

An e2e suite that selects on the left-hand column:

| Was                                                                          | Is now                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ring-autocomplete[-<suffix>]` on both the root and the inner text field     | `ring-autocomplete[-<suffix>]` on the root only; the field is `-textfield`, its input `-input`                                                                                                                                  |
| `ring-actionbox[-<suffix>]-item-<localized label>`                           | `ring-actionbox[-<suffix>]-item-<index>` (ids no longer contain spaces or change with the UI language)                                                                                                                          |
| `ring-actionbox[-<suffix>]-item-<label>` on a menu another component renders | `<owner-id>[-<control>]-menu-item-<index>`, e.g. `ring-textfield[-<suffix>]-menu-item-0`, `ring-datatoolbar[-<suffix>]-sort-menu-item-0`, `ring-autocomplete[-<suffix>]-menu-item-0`, `ring-splitbutton[-<suffix>]-menu-item-0` |
| `ring-comments[-<suffix>]-<id>-…`                                            | `ring-comments[-<suffix>]-item-<id>-…` (create-panel selectors unchanged)                                                                                                                                                       |
| `ring-ranges-item-<code>[-<suffix>]-…`                                       | `ring-ranges[-<suffix>]-item-<code>-…`; the nested range picker is `ring-autocomplete[-<suffix>][-<code>]-range-select`                                                                                                         |
| `ring-placeholder-<variant>[-<suffix>]`                                      | `ring-placeholder[-<suffix>]-<variant>` (unsuffixed usage unchanged)                                                                                                                                                            |
| `ring-textfield-ring-fileuploader[-<suffix>]-url-input`                      | `ring-fileuploader[-<suffix>]-url` for the field, `-url-input` for its input; `ring-fileuploader[-<suffix>]` is the root and `-dropzone` the dropzone                                                                           |
| `image` (`LightBox`)                                                         | `ring-lightbox[-<suffix>]-image`; the root carries `ring-lightbox[-<suffix>]`                                                                                                                                                   |
| `ring-splitbutton[-<suffix>]` on the main button                             | on the root; the main button is `-main`                                                                                                                                                                                         |
| `ring-mediacard[-<suffix>]-item-<row>-<column>`                              | `ring-multimediagrid[-<suffix>]-item-<id>` (keyed by the item, not by grid position)                                                                                                                                            |
| `toggle-left-slot-button`                                                    | `ring-datatoolbar[-<suffix>]-toggle-left-slot`                                                                                                                                                                                  |
| `ring-media-icon-placeholder`, the empty `Ranges` row                        | now honour `dataTestIdSuffix`                                                                                                                                                                                                   |
| `Detail` child field ids without the `detail` marker when a suffix was set   | the `detail` marker is always present                                                                                                                                                                                           |

### What to change

Replace the selectors in the right-hand column. [Writing E2E tests](?path=/docs/introduction-writing-e2e-tests--docs)
lists every attribute per component.

Lists, grids and trees generate `ring-<component>[-<suffix>]-item-<id>` for every item, keyed off the item's own id so
the attribute survives sorting, filtering, paging and virtualization (`ContentList` items are `-item-<index>`,
`Autocomplete` chips `-chip-<index>`). Every item takes `dataTestId` or `itemDataTestIdSuffix`; `SortableList`,
`ContentList` and `MultimediaGrid` also take `getItemDataTestId`, and `RingDataGrid` takes `getRowDataTestId`:

```tsx
<SortableList

    items={[
        { id: 'a1' }, // ring-sortablelist-order-item-a1

        { id: 'c3', itemDataTestIdSuffix: 'featured' }, // ring-sortablelist-order-featured
    ]}
    // last resort when the items cannot carry the fields themselves:
    getItemDataTestId={(item, index) => undefined}
    …
/>
```

## [2.0.0] - `FileUploader` passes on only the files it takes

`onFilesSelected` now receives only the files that match `accept`, fit `maxFileSize` and — with `multiple` off — the
first acceptable file of a selection. This holds for picked files, dropped files and a file row's replacement. The
others go to the new `onFilesRejected`, each with a `FileUploaderRejectionReason`.

In 1.x a drop passed any type and any number of files, so an app could check the type in `onFilesSelected` and show
its own message. That check never sees a wrong file any more, so the message never appears. Move it to
`onFilesRejected`:

```tsx
// ✖ 1.x — the app checks what the uploader hands over
<FileUploader
    accept="audio/mpeg,.mp3"
    onFilesSelected={([file]) => {
        if (!file.name.toLowerCase().endsWith('.mp3')) {
            setError(`${file.name} is not an MP3 file.`);

            return;
        }

        upload(file);
    }}
/>

// ✔ 2.0.0 — the uploader rejects the file and says why
<FileUploader
    accept="audio/mpeg,.mp3"
    maxFileSize={500 * 1024 * 1024}
    onFilesSelected={([file]) => upload(file)}
    onFilesRejected={([{ file, reason }]) =>
        setError(
            reason === FileUploaderRejectionReason.FileTooLarge
                ? `${file.name} is larger than 500 MB.`
                : `${file.name} is not an MP3 file.`,
        )
    }
/>
```

List extensions next to MIME types in `accept`. A MIME type is compared with the type the browser reports for the
file, and browsers report different types for some formats — a `.wav` file is `audio/wav` in Chrome and `audio/x-wav`
in Firefox and Safari, and some files have no type at all — so `accept="audio/wav"` alone rejects a valid file in
some browsers, while `accept="audio/wav,.wav"` takes it everywhere.

## [2.0.0] - `SearchBox` is an outlined field

`SearchBox` is the field of `TextField`: an outlined input with the field border, fill and 8px corners, 40px tall, or
32px with `size="small"`. Its root is the field root (`MuiOutlinedInput-root`), so `sx` and `className` style the field
rather than a box around it. The clear X is an icon button named by `labels.clear` (default `Clear`).

### Where to look

- `<SearchBox` with an `sx` that sets `height`, `border`, `borderRadius` or vertical padding.
- DOM snapshots and selectors that reach inside `.ring-search-box` (`.MuiStack-root`, `.MuiInput-root`). The
  `ring-searchbox[-<suffix>]` ids stay; `-clear` is on the button now.

### What to change

- Set the height with `size` instead of `height` or padding in `sx`, and drop `borderRadius`.
- To draw the search without a frame, inside a toolbar that has its own, hide the outline and the fill; `border: 'none'`
  no longer reaches the frame.
- Regenerate DOM snapshots. A test can find the clear button by its name, `getByRole('button', { name: 'Clear' })`.

### Before and after

```tsx
// before — a box around the input
<SearchBox
    defaultValue=""
    searchFunc={setQuery}
    sx={{ height: '40px', borderRadius: '4px', border: 'none', paddingLeft: '8px' }}
/>

// after — the field itself: size sets the height, the outline and fill are hidden
<SearchBox
    defaultValue=""
    searchFunc={setQuery}
    size="medium"
    sx={{
        paddingLeft: 1,
        backgroundColor: 'transparent',
        '& .MuiOutlinedInput-notchedOutline': { border: 'none' },
    }}
/>
```
