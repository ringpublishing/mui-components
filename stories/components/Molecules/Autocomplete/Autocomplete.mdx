# Autocomplete

Autocomplete extends [MUI Autocomplete](https://mui.com/material-ui/react-autocomplete/) and accepts its props except `renderInput`; the `filter` and `chipsInput` variants accept fewer.

The Autocomplete component provides a text input enhanced with a panel of suggested options. It's useful for:

- Single or multiple value selection from a predefined list
- Free text input with suggestions (freeSolo mode)
- Asynchronous data loading
- Recently used items tracking
- Custom option rendering with captions and avatars

For AI-coloured selected chips and option rendering, see the [AI color](?path=/docs/design-ai-color--docs) design guide.

## Avatar

Show a leading avatar or image before each option label in the default renderer, without having to override `renderOption`.

- A string is treated as an image URL and rendered inside a circular `Avatar`

- Customize the string avatar (border, size, variant, …) via `slotProps.avatar`

## Avatar — customised

## Free solo — duplicate feedback

In `freeSolo` mode, MUI silently drops an entry that is already selected: neither `onChange` nor `onInputChange` is called, so the user gets no hint why pressing Enter did nothing. `duplicateEntryMessage` renders a message under the field in that case and puts the field in the error state until the next input or value change. Pass a callback to quote the rejected text in the message.

### Key Features:

- Works only with `multiple` and `freeSolo` — ignored otherwise
- Takes over `slotProps.textField.helperText` and `error` while it shows, then hands them back
- Identity follows `isOptionEqualToValue` (MUI's default is `===`) — pass a case-insensitive comparator to catch `Design` when `design` is already a chip
- `onDuplicateEntry` receives the rejected text for feedback of your own, e.g. a toast — no message needed

### Usage:

```tsx
<Autocomplete
    multiple
    freeSolo
    options={[]}
    isOptionEqualToValue={(option, value) => option.toLowerCase() === value.toLowerCase()}
    duplicateEntryMessage={(entry) => `"${entry}" is already on the list`}
    labels={{ title: 'Tags' }}
/>
```

## Recently used

Track and display recently selected items in a separate group. Items are stored in localStorage and persist across sessions.

### Key Features:

- Automatic grouping of recently used items
- Configurable limit for stored items (default: 3)
- `recentlyLocalStorageKey` is required; without it the component throws

### Configuration:

```typescript
labels={{
    title: 'search by',
    recentlyUsed: 'Recently used',
    recentlyUsedResults: 'Results',

recentlyLocalStorageKey="recentlyUsed"
recentlyUsedLimit={3}
```

## Menu list action

An autocomplete menu list can render multiple icon buttons after its heading. The `anchorRef` from an action can be passed to `ActionBox` to render a custom action menu below that icon button.

Use the `menuListActions` story control to edit the heading and action labels. The story adds refs and callbacks at render time:

```tsx
<Autocomplete
    options={options}
    labels={{ title: 'Search by' }}
    menuListActions={{
        label: 'Results',
        actions: [
            { label: 'Configure results', icon: <Settings2 />, anchorRef: configureRef },
            { label: 'More actions', icon: <MoreVertical />, onClick: handleMoreActions },
            {
                label: 'Save results',
                icon: <Save />,
                disabled: true,
                disabledReason: 'Select a result before saving',
            },
        ],
    }}
/>
```

## Chip actions

Use `renderChip` when selected values need their own interactive UI. The callback
is called separately for each selected option, so every chip can receive different
actions based on its own data. The returned node can contain the chip and an
`ActionBox` or any other supporting component.

`chipProps` contains the props provided by MUI Autocomplete, including the default
delete handler. Pass these props to the custom `Chip` to preserve chip removal.

`renderValue` takes precedence over `renderTags`, which takes precedence over
`renderChip`. Therefore, `renderChip` is used only with `multiple={true}` when
neither of the other callbacks is provided. The component warns on the console
when `renderChip` is ignored for one of these reasons.

Custom rendering returns exactly the node from the callback: the default label
tooltip is not added automatically. Add it explicitly when needed:

```tsx
renderChip={({ label, chipProps }) => (
    <Tooltip title={label}>
        <Chip {...chipProps} />
    </Tooltip>
)}
```

`chipProps` is already merged as `{ ...muiChipProps, ...slotProps.chip, label }`.
The computed `label` is applied last and stays consistent with the `label`
provided in the callback context. `slotProps.chip` may still override properties
such as `onDelete` or `disabled`.

## Sortable chips

With `sortableChips` (and `multiple`), the selected chips can be reordered by dragging.
The dragged chip follows the pointer slightly tilted, while a dashed indicator marks the
drop slot; the remaining chips reflow live, also across wrapped rows.

### Key Features:

- On drop, `onChange` receives the reordered value with the `reorder` reason
- A quick click still deletes (the "X") or activates the chip — dragging starts after a short hold
- Options need a stable identity: `getOptionKey`, an `id` field, or a unique label
- Pointer-only by design; the input's keyboard navigation is unchanged
- A controlled `value` stays authoritative: the new order shows once your handler stores it
- Ignored, with a console warning, without `multiple`, when `renderValue` / `renderTags` replaces
  the chip row, and when the component is `disabled` or `readOnly`
- `limitTags` is ignored, with a console warning: sortable chips render as one drag context, so
  every chip renders; sorting still works
- On `reorder`, `event` is a stand-in: its methods do nothing and `currentTarget` is not the input
- While a chip is dragged, and for 180ms after the drop, its `data-testid` matches two elements

```tsx
<Autocomplete
    multiple
    sortableChips
    onChange={(event, value, reason) => {
        if (reason === 'reorder') {
            // value is the full array in its new order
        }
    }}
/>
```

## Filter

Use `variant="filter"` for a compact filter trigger. Selected values are summarized as a count, while an outlined search field is displayed at the top of the options panel. The filter variant supports loading, custom option rendering, and recently used items. It does not render selected values, tags, chips, or trigger actions.

The popup search field receives focus when opened. Arrow keys, Enter, Escape, Page Up, and Page Down are forwarded to the underlying autocomplete list. Home and End retain their native text-caret behavior.

## Chips input

`variant="chipsInput"` turns the field into a free-text input that keeps every entry as a chip. It replaces the removed `ChipsInput`: `multiple` and `freeSolo` are implied (passing them is a type error), `options` is optional, and typed or pasted entries are strings.

Moving from `ChipsInput`? See [Migration FAQ → Breaking Version Upgrades → 2.0.0 → ChipsInput Migration](?path=/docs/migration-faq-breaking-version-upgrades-2-0-0-chipsinput-migration--docs).

### Key Features:

- Enter adds a chip; the same entry twice is rejected, with `duplicateEntryMessage` / `onDuplicateEntry` as feedback
- `validateEntry` colours invalid chips with the error colour; the entry is still added
- `createChipsOnPaste` (disabled by default) splits pasted text on `pasteSeparators` (default `,` `;` new line, tab) and replaces the typed text
- `chipMaxWidth` (default `150`) truncates long labels; the tooltip shows the full label

<Canvas of={Stories.ChipsInputVariant} />

### Chips input — validation

`validateEntry` returns `false` for an entry that should be flagged. The chip turns red, but the entry is still added. It is checked on every render, so chips passed through `value` are validated too.

<Canvas of={Stories.ChipsInputWithValidation} />

### Chips input — paste

With `createChipsOnPaste`, pasted text is split on `pasteSeparators`, fragments are trimmed, empty ones dropped, and entries already on the list rejected. The text typed in the input is replaced.

## Long value

Selected values longer than the field. A single value is cut off with an ellipsis while the field is not focused,
and the clear button and the actions stay at the right edge. A long chip is truncated to the width of the field and
keeps its delete glyph; in `variant="chipsInput"`, `chipMaxWidth` truncates chips earlier. Pass icons through
`actions`, so the field sizes and places them the same way in every Autocomplete.
