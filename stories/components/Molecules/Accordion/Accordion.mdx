# Accordion

A collapsible content container that extends MUI's Accordion component with additional features like integrated action buttons and customizable labels. Perfect for organizing content sections that can be expanded or collapsed by users.

## Key Features

- **Custom labels**: Set custom header content for each accordion
- **Composable header**: `label` accepts nodes, so extra summary columns are composed rather than configured
- **Action button**: Optional button in the header for quick actions
- **Multiple accordions**: Seamless styling for stacked accordions
- **Expandable icon**: Built-in expand/collapse indicator
- **Accessible**: Follows ARIA patterns for keyboard navigation
- **MUI integration**: Extends all MUI Accordion properties

## Header button

Accordion with an integrated action button in the header. The button click event is isolated from the expand/collapse action, allowing for additional functionality without expanding the accordion.

### Key Features:

- Button appears in the header next to the label, in the last column of the summary
- The label takes the first column, about a third of the width, and wraps there
- Button click doesn't trigger accordion expansion
- Useful for quick actions like "Edit", "Delete", or "Add"

> **DOM note.** MUI renders the accordion summary as a real `<button>`, and a `<button>` cannot
> legally contain another one. So when `buttonLabel` is set, the summary is rendered as a
> `<div role="button">` instead — MUI's `ButtonBase` keeps the keyboard and screen-reader behaviour
> (focus, `Enter`, `Space`). Without `buttonLabel` the summary stays a native `<button>`.
>
> A `disabled` accordion also keeps the native `<button>`, and the action is not rendered at all: a
> non-native element only receives `aria-disabled` and would still react to clicks, and inside a
> disabled `<button>` the action was already unreachable.

## Composition

The summary is a three-column grid: two columns of a third each and a last column for the action
button. Rather than exposing a prop per column, `label` accepts any node — the same approach MUI's
own `AccordionSummary` takes with its children — so a second column is simply a second element:

```typescript
<Accordion
  label={
    <>
      <Typography variant="body1" component="span">Accordion</Typography>
      <Typography variant="body1" component="span" color="text.secondary">Secondary</Typography>
    </>
  }
>
  <div>Opened accordion</div>
</Accordion>
```

### Key Features:

- Column widths come from the summary itself — do not set them at the call site
- `component="span"` is required: the summary renders as a `<button>`, and `body1` maps to `<p>`,
  which would be invalid DOM nesting
- A single label keeps the full summary width, so narrow containers are unaffected

## Usage Example

```typescript
import { Accordion } from '@ringpublishing/mui-components';
import { TextField } from '@mui/material';

function MyComponent() {
  return (
    <Accordion
      label="Personal Information"
      buttonLabel="Edit"
      buttonOnClick={() => console.log('Edit clicked')}
    >
      <TextField label="Name" fullWidth />
      <TextField label="Email" fullWidth />
    </Accordion>
  );
}
```

### Label and Content

- **`label`**: Header content displayed in the accordion summary (default: "Test"). A string is
  rendered as a `body1` label; pass nodes to compose additional columns
- **`children`**: Content displayed when accordion is expanded (required)

### Action Button

- **`buttonLabel`**: Text shown on the action button in header
- **`buttonOnClick`**: Click handler for the action button (receives React MouseEvent)

The action button is optional and only appears when `buttonLabel` is provided. The button click event is stopped from propagating to prevent triggering the accordion expansion.

### Styling

- **`variant`**: MUI Accordion variant ('elevation' | 'outlined' | 'borderless')
- **`sx`**: Custom styles using MUI's sx prop
- **`className`**: CSS class name applied to root element

Details padding comes from the theme. A `borderless` accordion gets 8px top and 16px sides and bottom; `outlined` and
`elevation` get 8px top and bottom and 16px sides.

### Testing

- **`dataTestIdSuffix`**: Suffix for data-testid attributes (e.g., "ring-accordion-\{suffix\}")
