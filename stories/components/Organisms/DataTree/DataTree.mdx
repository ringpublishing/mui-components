# DataTree

A tree component that displays hierarchical data with support for columns, checkboxes, drag-and-drop, search, dynamic loading, and controlled selection.

- Renders nested tree items with expand/collapse behavior
- Supports additional columns alongside the item label
- Checkbox selection with per-item control (enable, disable, hide)
- Drag-and-drop reordering and drop-in nesting via callbacks
- Built-in search with debounce and label highlighting
- Dynamic child loading with `loadItems` (opt-in, see [Dynamic loading](#dynamic-loading))
- Controlled or uncontrolled item selection
- localStorage persistence for dynamic items and last selection

## Dynamic loading

Give an item a `loadItems` function and its children are fetched the first time the user expands it, instead of being passed up front in `items`. Dynamic loading is built on [TanStack Query](https://tanstack.com/query) and is **opt-in**: a tree with only static `items` needs no extra package or import.

### Setup

Only needed when at least one item in your app uses `loadItems`.

1. Install TanStack Query (v4 or v5):

    ```bash
    npm install @tanstack/react-query
    ```

2. Call `enableTreeDynamicLoading()` once, in code that runs in the browser before a tree with `loadItems` renders: the app entry, or the module that renders the tree. Calling it again is harmless.

    ```tsx
    // main.tsx
    import { enableTreeDynamicLoading } from '@ringpublishing/mui-components/tree-dynamic-loading';

    enableTreeDynamicLoading();
    ```

    In a React Server Components app (Next.js App Router), call it from a client module, for example the `'use client'` component that renders your providers. A call in a server component or layout never runs in the browser, where the trees render.

You do not need a `QueryClientProvider`: each tree creates its own `QueryClient` unless you [pass one in](#external-queryclient).

**Why a separate entry?** The main `@ringpublishing/mui-components` entry never references `@tanstack/react-query`, in code or in types, not even through a lazy `import()`. Apps that don't use `loadItems` therefore build, type-check and run without the package, whatever the bundler (Vite, webpack, Rspack, Next.js) and however the app splits vendor chunks. Only apps that import `tree-dynamic-loading` pull it in. Enabling is a function call rather than a bare `import '…'`, so tree-shaking and lint rules cannot silently drop it.

If a tree with `loadItems` renders before `enableTreeDynamicLoading()` ran, it throws during render:

```text
DataTree: items with `loadItems` need dynamic loading enabled. Call `enableTreeDynamicLoading()` from '@ringpublishing/mui-components/tree-dynamic-loading' once in your app and install `@tanstack/react-query` (^4 || ^5).
```

The error is not sticky: once `enableTreeDynamicLoading()` has run, the next render of the tree (for example after an error boundary resets) works without a page reload.

**Enabling without the package installed breaks the app,** in a way that depends on the bundler: webpack, Rspack and Vite 7 or older fail the build (`Module not found` / `"useQuery" is not exported by …`); Vite 8 only warns (`IMPORT_IS_UNDEFINED`) and the app fails at runtime when a tree with `loadItems` loads, or at startup if a `manualChunks` rule puts the library in a vendor chunk. Install `@tanstack/react-query` whenever you call `enableTreeDynamicLoading()`.

### How it works

1. **Static or dynamic.** On every render the tree checks `items` (nested static `items` included) for a `loadItems` function. With none, it renders the static implementation and TanStack Query is never loaded. With at least one, it renders the dynamic implementation instead, which needs [`enableTreeDynamicLoading()`](#setup) to have run.
2. **Lazy implementation.** The dynamic implementation and TanStack Query are code-split and fetched the first time a tree with `loadItems` renders. Until they arrive the tree shows a loading skeleton. Later trees on the page reuse the loaded code.
3. **Expand icon.** An item with `loadItems` shows the expand (+) icon before its children load.
4. **First expand.** Nothing is fetched until the item is expanded. On the first expand, `loadItems(item)` is called with the item itself, `onExpand(itemId)` fires as usual, and the icon turns into a spinner while the call is pending.
5. **Children.** The returned items render as the item's children. They are full tree items: column values, `withCheckbox` / `checked`, `rowActions`, `element`, their own `loadItems` (nested lazy branches) and so on all work as on static items.
6. **Caching.** The result is cached per item and never goes stale: collapsing and expanding again shows the cached children without calling `loadItems`. TanStack Query's garbage collection still applies to items that leave the tree, for example when their parent is collapsed for longer than `gcTime` (5 minutes by default); they load again on their next expand.
7. **Errors.** If `loadItems` throws or its promise rejects, the icon becomes a red refresh button (`data-testid` `ring-datatree[-<suffix>]-item-<id>-refresh`). There is no automatic retry; clicking the button calls `loadItems` again.
8. **Search.** `withSearch` filters static items and children that have already been loaded. Branches that were never expanded are not searched, and searching never triggers `loadItems`.

### Writing `loadItems`

```ts
loadItems?: (item: DataTreeItem) => Promise<DataTreeItem[]> | DataTreeItem[];
```

- Return the children of `item`, as an array or a promise of one. To make the next level lazy too, put a `loadItems` on the returned items. The same function can be reused at every level:

    ```tsx
    const loadItems = async (item: DataTreeItem): Promise<DataTreeItem[]> => {
        const children = await api.getChildren(item.itemId);

        return children.map((child) => ({
            itemId: child.id,
            label: child.name,
            ...(child.hasChildren ? { loadItems } : {}),
        }));
    };
    ```

- Return `[]` for an empty branch. The item then has no children and loses its expand icon, like an item without `items`.
- `itemId` must be unique across the whole tree, loaded items included. Cached results are keyed by `itemId`.
- Do not set both `items` and `loadItems` on the same item. Static `items` take precedence and the loaded result is never shown.
- A new `loadItems` function reference does not refetch. Cached children stay until the tree remounts or you [refresh them](#refreshing-loaded-children).
- Whether a tree is dynamic is decided from the current `items`. If `loadItems` first appears after mount (for example once your data arrives), the tree remounts with the dynamic implementation and loses uncontrolled expansion and selection state. Include `loadItems` from the first render, or control `selectedItems` and use `persistence`.

### Refreshing loaded children

Loaded children never go stale on their own. To reload them:

- **Whole tree:** remount it, for example by changing its `key`. The internal `QueryClient` is created per mount, so the cache starts empty (unless `persistence.cacheKey` restores it from localStorage).
- **One item:** pass your own [`queryClient`](#external-queryclient) with a `queryKeyPrefix` and invalidate that item's query. Its key is `['dataTreeItem', queryKeyPrefix, itemId]`. An expanded item reloads immediately; a collapsed one reloads on its next expand.

    ```tsx
    <DataTree items={items} queryClient={queryClient} queryKeyPrefix="files" />;

    queryClient.invalidateQueries({ queryKey: ['dataTreeItem', 'files', 'documents'] });
    ```

### Testing trees with `loadItems`

In unit tests (Vitest or Jest with Testing Library), enable dynamic loading once in your test setup file:

```ts
// vitest.setup.ts
import { enableTreeDynamicLoading } from '@ringpublishing/mui-components/tree-dynamic-loading';

enableTreeDynamicLoading();
```

Render the tree inside `ThemeConfig`, as in the app: the tree reads Ring theme tokens. The dynamic implementation loads asynchronously, so the first render of a tree with `loadItems` shows the skeleton. Wait for content with `findBy*` queries:

```tsx
render(
    <ThemeConfig mode="light">
        <DataTree items={[{ itemId: 'docs', label: 'Documents', expanded: true, loadItems }]} />
    </ThemeConfig>,
);

expect(await screen.findByText('Q1 Report.pdf')).toBeInTheDocument();
```

## Persistence

Pass a `persistence` object with a `cacheKey` to enable localStorage caching of dynamically loaded items. Use `restoreExpandedItems` and `restoreSelectedItem` to restore the tree state across page reloads.

```tsx
<DataTree
    items={items}
    persistence={{
        cacheKey: 'my-data-tree',
        restoreExpandedItems: true,
        restoreSelectedItem: true,
    }}
/>
```

- **`cacheKey`** (required): Unique key used to namespace the localStorage entries. Use different keys for different tree instances.
- **`restoreExpandedItems`** (optional): When `true`, the expanded items are persisted and restored on mount.
- **`restoreSelectedItem`** (optional): When `true`, the selected item(s) are persisted and restored on mount. Only applies in uncontrolled mode (when `selectedItems` prop is not provided).

`restoreExpandedItems` and `restoreSelectedItem` work on static trees too. Caching loaded children only applies to trees with `loadItems`, and so needs the [dynamic loading setup](#setup). After a reload, restored children appear immediately. Functions can't be stored in localStorage, so `loadItems` runs again in the background for each restored expanded branch: this refreshes the data and makes deeper levels expandable again.

## External QueryClient

**Requires the [dynamic loading setup](#setup).**

If your app already runs TanStack Query, pass your existing client through the `queryClient` prop instead of letting the tree create its own. This keeps tree queries visible in React Query DevTools, lets you invalidate or prefetch them programmatically, and shares cache policies (retry, staleTime, error handlers) with the rest of your app. The prop is ignored for trees without `loadItems`.

The prop is typed as `TreeQueryClient`, which any TanStack Query `QueryClient` (v4 or v5) satisfies. It describes the client by shape, so the package's types don't import `@tanstack/react-query`. Pass your `QueryClient` instance as is.

Set `queryKeyPrefix` to keep the cache across remounts (for example in tabs) and to address an item's query. Give each tree that shares the client a prefix of its own: trees with the same prefix show each other's cached children.
