# MediaCard

MediaCard is a versatile component for displaying multimedia resources such as photos, videos, podcasts along with additional information and actions.

- **Media Display** - handles images, videos, and custom elements
- **Customization** - configurable appearance with different aspect ratios and fitting methods
- **Status Labels** - ability to display status labels over the image and control their visibility on hover
- **Actions** - set of actions available to the user
- **Selection** - optional checkbox for card selection
- **Active state** - visual effects when hovering and selecting
- **Information Fields** - ability to add descriptions below the image

The component is built with flexibility in mind and can be used in various scenarios - from photo galleries to advanced asset management interfaces.

For AI-related status labels and gradient usage, see the [AI color](?path=/docs/design-ai-color--docs) design guide.

## Default

Basic configuration of the MediaCard component with the most commonly used properties.

### Available Variants

MediaCard supports the following main variants:

- **outlined** (default) - card with a border
- **elevation** - card with a shadow

### Basic Properties

| Property    | Type                                                       | Default      | Description                     |
| ----------- | ---------------------------------------------------------- | ------------ | ------------------------------- |
| `title`     | `string`                                                   | -            | Title of the card               |
| `variant`   | `'outlined' \| 'elevation'`                                | `'outlined'` | Style of the card               |
| `square`    | `boolean`                                                  | `false`      | Disable rounded corners         |
| `ratio`     | `string \| number`                                         | `'4/3'`      | Aspect ratio of the image       |
| `objectFit` | `'contain' \| 'cover' \| 'fill' \| 'none' \| 'scale-down'` | `'contain'`  | How the image should fit        |
| `image`     | `string`                                                   | -            | URL of the image                |
| `fields`    | `MediaCardFieldsItem[]`                                    | -            | List of fields with information |

```jsx
<MediaCard
    title="Resource title"
    variant="outlined"
    square={false}
    image="https://example.com/image.jpg"
    ratio="16/9"
    objectFit="cover"
    fields={[{ value: 'Author / Source' }, { value: 'Brief description or summary of the content' }]}
    sx={{ width: '300px' }}
/>
```

## Aspect ratio

The MediaCard component allows you to control the aspect ratio of the displayed image using the `ratio` prop.

- Default aspect ratio is `4/3`
- You can change the ratio by providing a custom value, e.g., `9/16`, `4/3`, `1/1`, etc.

### Image Fitting (objectFit)

The `objectFit` prop determines how the image should be fitted within the MediaCard dimensions.

| Parameter    | Description                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------- |
| `contain`    | The image will fit entirely within the space while maintaining its aspect ratio             |
| `cover`      | The image will fill the entire space while maintaining its aspect ratio, but may be cropped |
| `fill`       | The image will fill the space without maintaining aspect ratio                              |
| `none`       | The image will retain its original dimensions                                               |
| `scale-down` | Similar to contain, but never enlarges the image beyond its natural size                    |

### Image Behavior

- If the image aspect ratio differs from the MediaCard's set ratio, the image will be adjusted according to the `objectFit` value
- With `objectFit: "cover"`, the image may be cropped to fill the entire space
- With `objectFit: "contain"`, the entire image will be visible, but there may be empty spaces

```jsx
<MediaCard ratio="9/16" objectFit="cover" />
<MediaCard ratio={1} objectFit="contain" />
<MediaCard ratio="4/3" objectFit="fill" />
```

## Status labels

Status labels render as 16px tag chips (`Chip variant="tag"`) over the top-left corner of the image. `default`,
`primary` and `secondary` become the grey `stone` tag. `tip` shows a tooltip; without it the label text is the native
`title`.

Each object in the array can have the following properties:

| Property      | Type              | Description                                                     |
| ------------- | ----------------- | --------------------------------------------------------------- |
| `label`       | `string`          | The text to be displayed on the status label                    |
| `color`       | `string`          | Chip colour of the label (default `error`)                      |
| `icon`        | `React.ReactNode` | (Optional) An icon to be displayed alongside the label          |
| `showOnHover` | `boolean`         | (Optional) Parks the label behind the left edge until hover     |
| `tip`         | `string`          | (Optional) Tooltip text for the label                           |
| `key`         | `string`          | (Optional) Unique key for the label, useful for React rendering |

## Hoverable

`hoverable` adds a pointer and a scrim on hover that follows the colour mode. `active` tints the card with
`primary.main` at the selected opacity. The card keeps no state of its own: set `active` from `onClick`.

### Props

| Prop        | Type       | Default | Description                                                                |
| ----------- | ---------- | ------- | -------------------------------------------------------------------------- |
| `hoverable` | `boolean`  | `false` | Enables the hoverable functionality                                        |
| `active`    | `boolean`  | `false` | Indicates the current active/highlighted state                             |
| `onClick`   | `function` | -       | Callback function that will be called after clicking on the card component |

### Functionality

When the hoverable feature is enabled (`hoverable={true}`):

1. **Active tint**: the card shows the `active` tint; toggle `active` in the `onClick` callback.
2. **Interactive area**: the whole card shows the hover scrim, so the user sees it can be clicked.
3. **Active state**: the parent component owns it. `MediaCard` receives it through props and reports clicks through the
   callback.

```jsx
const [active, setActive] = useState(false);

<MediaCard hoverable={true} active={active} onClick={() => setActive(!active)} />;
```

### Important Notes

- The `MediaCard` component itself does not manage the hover state. It relies on the parent component to control this.
- When `hoverable` is `false`, the component behaves as a standard, non-interactive `MediaCard`.

## Checkbox

`slotProps.checkbox` adds a MUI `Checkbox` (`color="overlay"`) in the top-right corner of the image.

### Notes

1. The parent component should manage the checkbox's `checked` state.
2. The implementation uses an `onClick` callback, which provides information about state changes to the parent component.
3. In the click event handler, `event.stopPropagation()` should be called to prevent the event from bubbling up to parent elements.
4. `slotProps.checkbox.showOnHover` hides the checkbox until the card is hovered.

```jsx
const [checked, setChecked] = useState(false);
const handleCheckboxChange = (event) => {
    setChecked(!checked);
    event.stopPropagation();
};

<MediaCard
    slotProps={{
        checkbox: {
            checked,
            onClick: handleCheckboxChange,
            showOnHover: !checked,
        },
    }}
    statusLabels={[
        {
            label: 'New Feature',
        },
    ]}
/>;
```

## Actions

`actions` opens an `ActionBox` menu from the ⋮ button beside the title; `actionsAriaLabel` names the button (default
`More actions`). Each action conforms to the `Action` interface.

### Notes

- Actions are rendered in the order they are defined in the array.
- Disabled actions are still visible but cannot be clicked.
- Icons are optional and can be omitted if not needed.

Each entry in `fields` accepts `alwaysShowTooltip`, which shows the tooltip on hover even when the row does not overflow, and `tooltipTitle`, which replaces the tooltip content with any node. ## Card events

`MediaCard` exposes the underlying MUI `<Card>` element through the `slotProps.card` channel. Any prop that the `Card` component accepts is forwarded to the root element — including all native DOM event handlers.

### Common Use-Cases

- **Hover-driven interactions** — `onMouseEnter` / `onMouseLeave` to trigger a video preview, fetch on demand, or update tooltips.
- **Keyboard accessibility** — `onKeyDown` / `onFocus` / `onBlur` to integrate the card into custom keyboard navigation.
- **Right-click menus** — `onContextMenu` for custom action menus.
- **Accessibility attributes** — `aria-*`, `role`, `aria-describedby`, etc.
- **Test hooks** — `data-*` attributes beyond the built-in `dataTestIdSuffix`.

### Precedence

Top-level `MediaCardProps` (`variant`, `square`, `tabIndex`, `onClick`, `className`, `sx`) take precedence over values supplied through `slotProps.card`. They are merged on top — top-level wins. Use `slotProps.card` for everything that is not already exposed at the top level. `elevation` is excluded from `slotProps.card` because MediaCard manages it implicitly via `variant` — overriding would diverge from the design system.

```jsx
<MediaCard
    slotProps={{
        card: {
            onMouseEnter: () => setHovered(true),
            onMouseLeave: () => setHovered(false),
            onContextMenu: (e) => {
                e.preventDefault();
                openMenu();
            },
            'aria-label': 'Open detail view',
        },
    }}
/>
```

## Slots

The MediaCard component offers a slot system that allows for advanced customization by replacing default parts of the component with your own implementations.

### Available Slots

| Slot        | Type        | Default     | Description                                                                                                                                                 |
| ----------- | ----------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mediaCard` | `ReactNode` | `CardMedia` | Custom React node rendered in place of the default `<CardMedia>`. Wrapped in `<AspectRatio>` so `ratio` and `objectFit` still apply to the surrounding box. |
| `footer`    | `ReactNode` | —           | Optional custom footer rendered below the card content (inside `<CardActions>`).                                                                            |

### Using Slots

Slots provide full control over the behavior and appearance of specific parts of the component while maintaining the overall style and functionality of the MediaCard. This is particularly useful when you need to:

1. **Replace the default image display element** with your own, such as a video player, interactive visualization, or other React component.
2. **Add advanced features** that are not available in the default implementation.

```jsx
<MediaCard
    slots={{
        mediaCard: (
            <video controls autoPlay muted>
                <source src="path/to/your/video.mp4" type="video/mp4" />
                Your browser does not support video playback.
            </video>
        ),
    }}
    ratio="16/9"
    title="My video"
/>
```

## Slot props

The `slotProps` prop lets you forward arbitrary props to the internal sub-components without redefining each one as a top-level MediaCard prop. It mirrors the [MUI `slotProps` convention](https://mui.com/material-ui/customization/slots-and-classes/).

| Slot prop   | Type                                                                                             | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `card`      | `Omit<CardProps, "children" \| "variant" \| "square" \| "onClick" \| "tabIndex" \| "elevation">` | Props applied to the root MUI `<Card>`. **Recommended channel for native DOM events** (`onMouseEnter`, `onMouseLeave`, `onFocus`, `onKeyDown`, `aria-*`, `data-*`, …). Top-level MediaCardProps (`variant`, `square`, `onClick`, `tabIndex`, `className`, `sx`) take precedence and are merged on top. `elevation` is excluded because MediaCard manages it implicitly via `variant` (`outlined` → 0, `elevation` → 1) — overriding it would diverge from the design system. |
| `cardMedia` | `Omit<CardMediaProps<'img'>, 'component'>`                                                       | Props applied to the default `<img>`. Used **only** when `slots.mediaCard` is not provided. `component` is fixed; setting this slot skips the skeleton and the placeholder.                                                                                                                                                                                                                                                                                                  |
| `checkbox`  | `CheckboxProps & { showOnHover?: boolean }`                                                      | Props applied to the selection `<Checkbox>`. The custom `showOnHover` flag hides the checkbox until the card is hovered (useful for grid scenarios). When `undefined`, the checkbox is not rendered.                                                                                                                                                                                                                                                                         |
| `footer`    | `CardActionsProps`                                                                               | Props applied to the `<CardActions>` element wrapping `slots.footer` (e.g. `sx`, `disableSpacing`).                                                                                                                                                                                                                                                                                                                                                                          |

### Precedence rules

When the same prop can be supplied through more than one channel:

- **`variant`, `square`, `onClick`, `tabIndex`** — only top-level MediaCardProps. Excluded from `slotProps.card` typing to prevent accidental override.
- **`className`, `sx`** — additive: top-level value is **merged on top of** `slotProps.card` value (for `className` they are concatenated, for `sx` they form an array layer).
- **All other props** — supplied through `slotProps.card` are forwarded to `<Card>` directly.

```jsx
<MediaCard
    slotProps={{
        card: {
            onMouseEnter: () => setHovered(true),
            onMouseLeave: () => setHovered(false),
            onContextMenu: (e) => {
                e.preventDefault();
                openMenu();
            },
            'aria-label': 'Open detail view',
        },
        checkbox: { checked, onClick: toggle, showOnHover: !checked },
    }}
/>
```

## Placeholder

The MediaCard component displays a placeholder when the media source is unavailable.

By default, it shows the lucide `Image` icon on a `FeaturedIcon` plate sized from the frame. A different icon passed
through `iconPlaceholder` gets the same plate; `null` or `false` leaves the frame empty.

```jsx
import { Video } from 'lucide-react';

<MediaCard iconPlaceholder={<Video />} />;
```

## Image load error

While the image loads, the card shows a skeleton. When it fails, the placeholder shows the `ImageOff` icon instead of
`iconPlaceholder`, so a broken image reads differently from a missing one.
