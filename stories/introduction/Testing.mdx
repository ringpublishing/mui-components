# Writing E2E tests

UI testing ensures that the front-facing aspect of an application works as intended. UI tests are a great tool for catching regressions.

Ring Publishing uses [Playwright](https://playwright.dev/) as the primary framework for end-to-end UI testing. In recent years,
it has become the de facto standard for UI testing in the JavaScript ecosystem.
Playwright allows you to write tests that simulate user interactions with your application in a real browser environment.

# `data-testid` attributes

Ring UI Components are meant to provide a coherent set of common building blocks for Ring Publishing developers.
Therefore, we include a range of `data-testid` attributes in our components to facilitate easier selection of elements during testing.
Not every component includes `data-testid` attributes. In most cases they are added to components that have inputs or other interactive elements
that may be hard to locate by other means than `data-testid`.

When writing tests, you should not rely on `data-testid` attributes unless necessary. **When creating locators in your tests,
you should prefer more user-centric selectors, such as text content, roles, or labels**. After all, it is the placeholder texts, labels, etc. that users will see.
This way your tests will be less tightly coupled with the UI implementation details and more resilient to changes in the underlying components.
We acknowledge that there are cases when using `data-testid` attributes is unavoidable and much more convenient, thus they are included across the Ring UI Components.

## How are `data-testid` attributes named?

When adding a `data-testid` attribute to a Ring UI Component, we follow a consistent naming convention:
`ring-<component>[-<suffix>]` on the root, `-item-<id>` (or `-item-<index>` where items have no id) on repeated children, and `<owner-id>-…` for anything a component renders on another component's behalf.

An id is built from these parts:

- `ring` - a common prefix for all Ring UI Components
- `<component>` - the component name, lower-cased (`editabletext`, `datatoolbar`)
- `<suffix>` - an optional value set through the common `dataTestIdSuffix` prop.
- `<element>` - a specific part of the component that a developer may want to locate (e.g., `input`, `button`)

Which in combination results in the following format:

```
data-testid="ring-<component>[-<suffix>][-<element>]"
```

Generated segments, suffix and item ids included, are lower-cased; verbatim overrides are not.

For example, an `Autocomplete` in its `chipsInput` variant renders the following attributes:

```jsx
import { Autocomplete } from '@ringpublishing/mui-components';
import { Box } from '@mui/material';

function ExampleComponent() {
    return (
        <Box>
            <Autocomplete
                variant="chipsInput"
                dataTestIdSuffix="custom-suffix"
                labels={{
                    title: 'Chips input',
                    inputPlaceholder: 'Insert value and press enter',
                }}
                validateEntry={(value) => {
                    return !isNaN(parseInt(value));
                }}
                onChange={(event, value) => console.log(value)}
            />
        </Box>
    );
}
```

With one chip added, it renders as follows (classes, styles and icon paths left out):

```html
<div data-testid="ring-autocomplete-custom-suffix">
    <div data-testid="ring-autocomplete-custom-suffix-textfield">
        <label data-shrink="true" for=":r5f:" id=":r5f:-label">Chips input</label>
        <div>
            <div
                tabindex="-1"
                role="button"
                data-item-index="0"
                data-testid="ring-autocomplete-custom-suffix-chip-0"
                aria-label="abc"
                data-mui-internal-clone-element="true"
            >
                <span>abc</span>
                <svg aria-hidden="true" viewBox="0 0 24 24"><path d="…"></path></svg>
            </div>
            <input
                aria-invalid="false"
                autocomplete="off"
                id=":r5f:"
                data-testid="ring-autocomplete-custom-suffix-input"
                aria-autocomplete="list"
                aria-expanded="false"
                autocapitalize="none"
                spellcheck="false"
                role="combobox"
                type="text"
                value=""
            />
            <div>
                <button tabindex="-1" type="button" aria-label="Clear" title="Clear">
                    <svg aria-hidden="true" viewBox="0 0 24 24"><path d="…"></path></svg>
                </button>
            </div>
            <fieldset aria-hidden="true">
                <legend>
                    <span>Chips input</span>
                </legend>
            </fieldset>
        </div>
    </div>
</div>
```

Note the following `data-testid` attributes:

- `data-testid="ring-autocomplete-custom-suffix"` on the root element of the `Autocomplete` component,
- `data-testid="ring-autocomplete-custom-suffix-textfield"` on the text field inside it,
- `data-testid="ring-autocomplete-custom-suffix-chip-0"` on the first chip element within the `Autocomplete`,
- `data-testid="ring-autocomplete-custom-suffix-input"` on the input element within the `Autocomplete`.

Note that the `dataTestIdSuffix` is optional. If not provided, the `data-testid` attributes would be named without the suffix part, e.g., `data-testid="ring-autocomplete"`.

Ids of components rendered inside another hang off the owner's id (`<owner-id>-menu-item-0`) or reuse its `dataTestIdSuffix` (`SearchBar` → `ring-searchbox[-<suffix>]`).

## Targeting items in list components

`DataGrid`, `MultimediaGrid`, `SimpleTree`, `DataTree`, `TreeView`, `ContentList` and
`SortableList` expose three levels of `data-testid`:

1. **The component** — `ring-<component>[-<suffix>]`, from the list's own `dataTestIdSuffix`.
2. **Every item** — `ring-<component>[-<suffix>]-item-<id>`, generated automatically.
3. **One specific item** — set `dataTestId` on that item to replace its attribute verbatim, or
   `itemDataTestIdSuffix` to replace only the `item-<id>` segment.

```typescript
<MultimediaGrid
    dataTestIdSuffix="gallery"
    items={[
        { id: 'a1', title: 'A' }, // ring-multimediagrid-gallery-item-a1
        { id: 'b2', title: 'B', dataTestId: 'hero-card' }, // hero-card
        { id: 'c3', title: 'C', itemDataTestIdSuffix: 'featured' }, // ring-multimediagrid-gallery-featured
    ]}
/>
```

When the item objects cannot carry those fields, pass `getItemDataTestId(item, index)` to
`ContentList`, `MultimediaGrid` or `SortableList` instead (`getRowDataTestId(row, index)` on
`DataGrid`; the trees have neither) and return `undefined` for any item that should keep its
default. `index` is the item's position in the flat list — in a grid it counts items, not rows.

Item ids are keyed off each item's own identifier rather than its position, so they survive
sorting, filtering, paging and virtualization.

## `data-testid`s available in Ring UI Components

Below is a list of Ring UI Components that include `data-testid` attributes, along with the specific elements that can be targeted within each component.

### Atoms

#### `Alert`

- `ring-alert[-<suffix>]` - The root element of the `Alert` component.
- `ring-alert[-<suffix>]-close` - The close button.
- `ring-alert[-<suffix>]-action` - The action button.

#### `CopyIconButton`

- `ring-copyiconbutton[-<suffix>]` - The button. It also carries `data-copied`: `true` for `copiedForMs` after a
  successful copy, `false` otherwise.

#### `DatePicker`, `DateTimePicker`, `TimePicker`

- `ring-datepicker[-<suffix>]` / `ring-datetimepicker[-<suffix>]` / `ring-timepicker[-<suffix>]` - The field root.
- `…[-<suffix>]-clear` - The clear button (when `actions` are provided; `DatePicker`, `DateTimePicker` only).
- `…[-<suffix>]-actions` - The actions button (when `actions` are provided; `DatePicker`, `DateTimePicker` only).
- `…[-<suffix>]-menu-item-<index>` - Each item in the actions menu (`DatePicker`, `DateTimePicker` only).

You can use the `data-testid` attribute to locate the component and focus it in order to enter the date/time.
An example of how it can be implemented is presented in the following code snippet:

```typescript
test('Should find and fill DatePicker component', async ({ page }) => {
    await page.goto(YOUR_APPLICATION_URL);
    const datePickerElement = page.getByTestId('ring-datepicker');

    await datePickerElement.click();
    await datePickerElement.getByRole('spinbutton', { name: 'Day' }).fill('01');
    await datePickerElement.getByRole('spinbutton', { name: 'Month' }).fill('12');
    await datePickerElement.getByRole('spinbutton', { name: 'Year' }).fill('2025');

    // Perform some assertions ...
});
```

#### `FeaturedIcon`

- `ring-featuredicon[-<suffix>]` - The root element of the `FeaturedIcon` component; `dataTestId` (or `data-testid`)
  replaces it verbatim.

#### `EditableText`

- `ring-editabletext[-<suffix>]` - The root element of the `EditableText` component.
- `ring-editabletext[-<suffix>]-text` - The displayed text element.
- `ring-editabletext[-<suffix>]-edit` - The edit button.
- `ring-editabletext[-<suffix>]-input` - The input element (rendered in edit mode).

#### `Switch`

- `ring-switch[-<suffix>]` - The root element of the `Switch` component.
- `ring-switch[-<suffix>]-input` - The input element.

#### `TextField`

- `ring-textfield[-<suffix>]` - The root element of the `TextField` component.
- `ring-textfield[-<suffix>]-input` - The input element within the `TextField` component.
- `ring-textfield[-<suffix>]-action` - The single action button.
- `ring-textfield[-<suffix>]-actions` - The actions button.
- `ring-textfield[-<suffix>]-menu-item-<index>` - Each item in the actions menu.

Passing `dataTestId` (or `data-testid`) to a `TextField` replaces the root id **and** prefixes the input,
action and menu ids with it, so two fields told apart only by a custom id do not collide.

#### `Tooltip`

- `ring-tooltip[-<suffix>]` - The element the tooltip is attached to (MUI `Tooltip` forwards the attribute to its child).

### Molecules

#### `Accordion`

- `ring-accordion[-<suffix>]` - The root element of the `Accordion` component.
- `ring-accordion[-<suffix>]-expand` - The expand/collapse button of the `Accordion` component.
- `ring-accordion[-<suffix>]-button` - The optional button element.

#### `ActionBox`

- `ring-actionbox[-<suffix>]` - The root element of a standalone `ActionBox`.
- `ring-actionbox[-<suffix>]-item-<index>` - Each action item, where `<index>` is the zero-based index of the action.

`dataTestId` (or `data-testid`) replaces the root id verbatim; the items then read `<that id>-item-<index>`.

Each action may override its own attribute with `dataTestId` (used verbatim) or
`itemDataTestIdSuffix` (replaces the `item-<index>` segment).

**When an `ActionBox` is nested inside another component** (`TextField`, `Autocomplete`, the date
pickers, `SplitButton`, `MediaCard`, `Media`, `ChipsGroup`, the trees, DataGrid action and combo
cells, the toolbars, `DataView`), it is namespaced to its owner instead — the ids read
`<owner-id>[-<control>]-menu` and `<owner-id>[-<control>]-menu-item-<index>`, e.g.
`ring-splitbutton[-<suffix>]-menu-item-0`. `<control>` is `show-more` on `ChipsGroup`, `sort` on the
toolbars, `actions` on `DataView` and `more` in a combo cell; the other owners have none. This keeps two
menus on one page distinct.

#### `Autocomplete`

- `ring-autocomplete[-<suffix>]` - The root element of the `Autocomplete` component.
- `ring-autocomplete[-<suffix>]-textfield` - The inner `TextField` wrapper (not rendered in the `filter` variant).
- `ring-autocomplete[-<suffix>]-input` - The input element.
- `ring-autocomplete[-<suffix>]-chip-<index>` - Each selected chip of a `multiple` field, keyed by its position in the
  committed order. Present with and without `sortableChips`, unless `slotProps.chip` sets its own attribute.
  While a chip is dragged the `DragOverlay` renders it a second time, so for the length of the drag (plus the 180ms
  drop animation) that id matches two elements — a mid-drag assertion needs `.first()`.
- `ring-autocomplete[-<suffix>]-action` - The action button (when a single action is provided).
- `ring-autocomplete[-<suffix>]-actions` - The button that opens the `ActionBox` (when multiple actions are provided).
- `ring-autocomplete[-<suffix>]-circular-progress` - The loading indicator (when `loading` is set).
- `ring-autocomplete[-<suffix>]-menu-item-<index>` - Each item in the actions menu.
- `ring-autocomplete[-<suffix>]-menu-list-action-<index>` - Each `menuListActions` button in the list heading.
- `ring-autocomplete[-<suffix>]-clear` - The clear button (`filter` variant only).
- `ring-autocomplete[-<suffix>]-popup` - The open/close button (`filter` variant only).
- `ring-autocomplete[-<suffix>]-search-input` - The search input in the popup (`filter` variant only).

#### `ChipsGroup`

- `ring-chipsgroup[-<suffix>]` - The root element of the `ChipsGroup` component.
- `ring-chipsgroup[-<suffix>]-show-more` - The "show more" chip.
- `ring-chipsgroup[-<suffix>]-show-more-menu-item-<index>` - Each chip in the overflow menu.
- `ring-chipsgroup[-<suffix>]-delete-all` - The "delete all" button.
- `ring-chipsgroup[-<suffix>]-expandable` - The "expandable" button.
- `ring-chipsgroup[-<suffix>]-chip-<index>-<position>` - Each chip within the `ChipsGroup` component, where `<index>` is the zero-based index of the chip and `<position>` is either _static_ or _fixed_.

#### `Media`

- `ring-media[-<suffix>]` - The root element of the `Media` component.
- `ring-media[-<suffix>]-actions` - The actions button within the `Media` component.
- `ring-media[-<suffix>]-menu-item-<index>` - Each item in the actions menu.
- `ring-media[-<suffix>]-icon-placeholder` - The icon placeholder within the `Media` component (a `FeaturedIcon`).
- `ring-media[-<suffix>]-image` - The image; a button that opens the full-screen preview when `image` is set and `disableFullScreenPreview` is not.
- `ring-editabletext[-<suffix>]-title` / `ring-editabletext[-<suffix>]-description` - The editable title and
  description (when `onTitleSubmit` / `onDescriptionSubmit` is set); their parts follow `EditableText`.
- `ring-lightbox[-<suffix>]` - The full-screen preview; its parts follow `LightBox`.

#### `Placeholder`

- `ring-placeholder[-<suffix>]-<variant>` - The root element of the `Placeholder` component.
- `ring-placeholder[-<suffix>]-<variant>-button-<index>` - Each button, where `<index>` is the zero-based index of the button.

#### `Ranges`

- `ring-ranges[-<suffix>]` - The root element of the `Ranges` component.
- `ring-ranges[-<suffix>]-item-<code>-from` - The "from" input of a range row, where `<code>` is the code of the range.
- `ring-ranges[-<suffix>]-item-<code>-to` - The "to" input of a range row.
- `ring-ranges[-<suffix>]-item-<code>-select-from` - The "from" select of a range row.
- `ring-ranges[-<suffix>]-item-<code>-select-to` - The "to" select of a range row.
- `ring-autocomplete[-<suffix>][-<code>]-range-select` - The range-picker `Autocomplete` of a range row (`<code>` is absent on the not-yet-chosen row).

Note that the `data-testid` attributes for select inputs are attached to `div` elements that wrap the actual select inputs,
so when writing tests, you will need to locate the inner element.

#### `SearchBox`

- `ring-searchbox[-<suffix>]` - The root element of the `SearchBox` component.
- `ring-searchbox[-<suffix>]-input` - The input element within the `SearchBox` component.
- `ring-searchbox[-<suffix>]-search` - The search icon.
- `ring-searchbox[-<suffix>]-clear` - The clear button.

#### `SearchBar`

- `ring-searchbar[-<suffix>]` - The root element of the `SearchBar` component.

#### `SplitButton`

- `ring-splitbutton[-<suffix>]` - The root element of the `SplitButton` component.
- `ring-splitbutton[-<suffix>]-main` - The main action button.
- `ring-splitbutton[-<suffix>]-dropdown` - The dropdown button.
- `ring-splitbutton[-<suffix>]-menu-item-<index>` - Each item in the dropdown menu.

#### `FeatureTooltip`

- `ring-featuretooltip[-<suffix>]` - The anchor element the tooltip is attached to. MUI `Tooltip`
  clones its child and the child's own props win, so this id is **not** applied when the child
  carries its own `data-testid`. The content and close ids below are always present — prefer them
  for asserting that a tooltip opened.
- `ring-featuretooltip[-<suffix>]-content` - The floating tooltip card.
- `ring-featuretooltip[-<suffix>]-close` - The close button of the tooltip.
- `ring-featuretooltip[-<suffix>]-button-primary` - The primary action button of the tooltip.
- `ring-featuretooltip[-<suffix>]-button-secondary` - The secondary action button of the tooltip.

Any single item can override its own attribute:

- `getRowDataTestId(row, index)` on the grid — overrides every row; return `undefined` to keep the default.

- `ring-datagrid[-<suffix>]-item-<rowId>-<field>` - The contents of a cell rendered by

  cell's menu.

- `ring-datagrid[-<suffix>]-item-<rowId>-<field>-placeholder-icon` - The placeholder of a combo cell without an image

# Auditing stories against the docs

`npm run test:stories:audit` statically checks that every story file is re-exported, rendered with `<Canvas>` in the
component's MDX, listed in Quick Navigation and paired with its own `stories/code/<Story>Example.tsx`, and it flags
examples whose props or rendered elements drift from the story. Pass a component name to narrow the scan
(`npm run test:stories:audit -- Autocomplete`); `--summary` prints only the counts.
